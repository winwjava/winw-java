# 双目摄像头实时 SLAM 与鸟瞰地图

已增加 Java Swing 实时窗口。运行时边采集左右图像、边估计相机运动并建立周围环境地图，窗口同步显示校正后的左右画面和鸟瞰图。

## 驾驶屏幕风格

默认使用浅色的驾驶场景视图：相机载体用汽车图标表示，位于画面下方中央，前方朝上，环境随实时朝向旋转。画面使用示意透视投影、米制距离参考曲线和已记录的轨迹。默认 OCC 模式显示三维占据体素；关闭 OCC 后，连接的历史几何表面显示包络。

窗口提供“驾驶视图”和“地图视图”按钮。“全图”切换到地图视图以查看完整环境；“驾驶视图”恢复跟随当前位姿。配置 `view.mode=DRIVING` 或 `view.mode=MAP` 选择初始模式。

驾驶显示与 SLAM 使用同一份实时数据，并非独立动画。汽车图标是相机载体的示意符号，不表示程序已经识别到汽车，也不表示实测车身尺寸。灰色包络来自连通点云的几何边界，可能跨越多个物体，并未做车辆/行人分类。距离曲线是标尺，不是检测到的车道线；蓝线是已经走过的轨迹，不是规划路线。

要进一步显示周围汽车、行人和实际车道，需要加入图像目标检测、车道/可行驶区域分割、双目深度融合以及时序跟踪。当前代码尚未具备这些语义感知能力，不将未知几何点伪装成分类结果。

`target/slam-driving-view-preview.png` 是合成几何场景下的新风格预览，标有合成示例提示；实际图像取决于相机观测和定位质量。

## 接入你的设备

需要确定摄像头型号、**单眼**分辨率、输出方式和标定文件。当前已实现同一个相机设备输出同步左右拼接图像：

| 相机输出 | 配置 |
| --- | --- |
| 左右并排 `left|right` | `camera.layout=SIDE_BY_SIDE` |
| 上下排列 `left/right` | `camera.layout=TOP_BOTTOM` |
| 左右顺序相反 | `camera.swapEyes=true` |

两个独立设备或厂商 SDK 的双目相机，需要按实际接口接入同步采集；本程序不将两路无同步保证的 USB 读取当成同步双目。

准备两个配置文件：

1. **真实标定文件** `my-camera.properties`：参考 [raw-example.properties](raw-example.properties) 或 [rectified-example.properties](rectified-example.properties) 的格式。示例参数不适用于未知设备，必须替换为实测参数。`width,height` 是单眼尺寸，基线单位为米。
2. **采集与显示配置**：复制 [live-example.properties](live-example.properties)，设置布局、顺序、帧率和地图显示参数。比如单眼 640×480 的左右拼接相机，请求总图像 1280×480；驱动必须实际输出这个尺寸。

从项目根目录运行，设备号默认常见为 `0`，但需按实际连接修改：

```powershell
.\docs\slam\run-slam.ps1 -Mode camera `
  -Calibration .\my-camera.properties `
  -InputSource 0 `
  -LiveConfig .\docs\slam\live-example.properties `
  -OutputDirectory .\target\my-room-map
```

启动时将相机水平、稳定地朝向有纹理的静态区域。初始化成功后缓慢平移和转动，尽量保留连续画面重叠，从不同位置观察房间。首帧位置成为地图原点。地图只能来自相机已经观察到的区域，遮挡后方和未观察方向不会自动补全。

Windows 若 AUTO 后端打不开设备，可尝试 `camera.backend=700`（DirectShow）或 `1400`（MSMF）；设备不支持 MJPG 时将 `camera.fourcc=` 留空。图像尺寸不匹配时程序报告实际和期望尺寸，不会默默缩放或裁剪而破坏标定。

## 窗口与操作

- 左侧驾驶视图：白色汽车图标表示当前相机载体，灰色表示观测几何表面及其包络，蓝色为已记录轨迹。切换到地图视图后，绿色/青绿色为表面，黄色点为关键帧，红色箭头为当前相机及朝向。
- 右侧是校正后的左右图像。底部显示跟踪状态、坐标、处理耗时/处理帧率、内点和地图规模；处理帧率是计算吞吐，不等于设备曝光帧率。
- 鼠标滚轮缩放、拖动平移；“跟随相机”保持相机在视图中心，“回到原点”恢复原点视图，“显示全图”适配已建立的地图范围。
- “保存鸟瞰图”保存当前视野。“停止并保存”或 ESC 停止采集，保存完整地图、轨迹和全图 PNG；关闭窗口时也先停止并保存，完成后可点“关闭”。
- 跟踪丢失时隐藏当前位置箭头，保留已建立地图；恢复后的轨迹开始新线段，不用直线伪造丢失期间的运动。
- 回环更新关键帧后，鸟瞰图中的深度云和历史轨迹同步修正。

采集和 SLAM 在后台线程执行，Swing 用最新快照以约 10 Hz 刷新，避免逐帧排队。真实计算速度取决于设备、分辨率、特征和关键帧规模，目前尚未在你的硬件上测量。

## 周围环境地图如何形成

使用 [OpenCV SGBM](https://docs.opencv.org/4.x/javadoc/org/opencv/calib3d/StereoSGBM.html) 计算稠密视差，进行米制三角化、距离过滤和下采样。默认 OCC 在有效定位帧按 `occ.frameInterval` 采样，新增关键帧也采样；同帧测量共用于 OCC 和关键帧历史云。历史云保存在关键帧局部坐标中，随优化位姿转换到世界坐标。关闭 `map.dense` 会同时关闭 OCC，只绘制 ORB 稀疏地图。

鸟瞰图将世界三维点投影到 X–Z 平面，按 `view.cellSize` 聚合为表面密度网格。没有 IMU 和地面拟合时，该平面是**初始化相机的水平参考平面**，需要初始相机近似水平；程序没有自动估计真实重力方向。

地图点高度过滤使用世界 `y`，正方向向下、原点在初始相机。假设初始相机在地面上方 1.2 米，地面约为 `y=+1.2`；设置 `view.maxY=0.8` 可减少地面点覆盖整个鸟瞰图。默认 `view.minY=-2`、`view.maxY=0.8` 应按安装高度调整；过滤过窄可能隐藏桌面、低矮物体或墙体局部。这里没有自动地面分割。

上述表面密度栅格是 `occ.enabled=false` 的历史点云模式。默认已开启三维 OCC：有效定位帧按配置间隔计算深度，用射线更新自由空间与表面占据概率，跨帧融合、过期撤销并在回环后重放。驾驶视图显示占据体素，地图视图用琥珀色表示占据、淡绿色表示完整高度范围内已观测自由列；未知区域保留背景。实现、参数和论文对应见 [三维 OCC 文档](OCCUPANCY.md)。这些状态没有提供导航可通行性判定。

## 输出

| 文件 | 内容 |
| --- | --- |
| `trajectory.tum` | 回环修正后的完整有效定位轨迹，单位米 |
| `map.ply` | ORB 稀疏关键帧地图 |
| `environment.ply` | SGBM 下采样后的环境三维云；关闭稠密模式时为稀疏点 |
| `occupancy.csv` | 启用 OCC 时，滚动窗口内体素概率、状态和观测帧数 |
| `occupancy.ply` | 启用 OCC 时，确认占据的体素中心及概率 |
| `bird-eye.png` | 停止时保存的全图鸟瞰快照 |

历史深度云可能包含误匹配或跨关键帧重复表面；OCC 另行提供概率体素融合，不改变原始历史云。当前没有共享 SLAM 地图点观测图或完整 BA。

## 离线动态回放

也可通过已有左右图清单验证动态地图，无需开启摄像头：

```powershell
.\docs\slam\run-slam.ps1 -Mode dataset-view `
  -Calibration .\my-camera.properties `
  -InputSource D:\datasets\sequence\manifest.txt `
  -LiveConfig .\docs\slam\live-example.properties `
  -OutputDirectory .\target\replay-map
```

清单格式见 [基础 SLAM 文档](README.md)。回放每帧增加 30 ms 等待以方便观察，使用清单真实时间戳估计轨迹，播放速度不保证与录制帧率一致。

## 验证和容量

`mvn -Pslam-tests test`：31 项测试通过。验证覆盖左右/上下拆分和交换、颜色转换、米制稠密深度、深度云随关键帧纠偏、负坐标网格、高度过滤、鸟瞰投影和丢失位姿绘制，以及驾驶视图转向投影、模式切换和预览输出。新增 12 项 OCC 测试详见 [OCCUPANCY.md](OCCUPANCY.md)。

测试生成 `target/slam-bird-eye-preview.png`，是**合成环境显示示例**，用于检查绘制，并非实机建图结果。摄像头采集、同步质量、实际精度和实时帧率仍需你的设备与真实标定验证。

默认最多 80 个关键帧，每帧最多约 5000 个下采样深度点。达到上限后继续在已有地图上定位，停止 SLAM 地图扩展和新增回环；窗口会显示容量状态。OCC 仍可在有效定位帧更新滚动局部环境。`slam.maxKeyframes` 可配置为 2–200，但后端采用稠密求解，提高上限会增加耗时。该原型适合短时、有限范围实验，长时间大范围建图还需要关键帧剔除和稀疏优化。
