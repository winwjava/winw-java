# Java/OpenCV 自然场景双目标定

在 IDE 直接运行 `StereoSlamDemo.main()`，或使用 `run-slam.ps1 -Mode camera-auto`。录制至少 25 对，建议 80～120 对，填写实测镜头光心间距（毫米），点击“自然场景标定并启动地图”。界面及 `run-auto-slam.ps1` 全部使用 Java 和项目已有的 OpenCV JNI，不启动 Python、pip 或 COLMAP，不需要联网安装标定组件。运行环境仍需匹配的 OpenCV 本地库，与相机预览相同。

修改相机参数后点击“应用并重启相机”；每次录制使用独立目录。单眼 640×480 的左右拼接流总尺寸为 1280×480。左右顺序和同步由设备保证；可用“交换左右眼”调整顺序。

预览使用 ORB 双向比率匹配、RANSAC 基础矩阵及投影校正。像素视差不表示米，`rectification.properties` 也不是米制标定，不能直接交给 `StereoRig`。

## 自标定方法与边界

`NaturalSceneCalibration` 最多选取 60 对；较长录制在全程均匀选取 12 段各 5 对的连续短片段，保留近邻重叠。每五对保留一对用于独立验证，其余训练帧按间隔 1、2、3、5、8、12 组进行跨时刻匹配。缓存 ORB 描述子及最长边不超过 960 px 的光流图像，限制内存占用。

ORB 特征不足时，在 CLAHE 局部对比度增强图像上以 FAST 阈值 7 重试。双目 ORB 匹配不足或覆盖不足时，使用缓存的 CLAHE+SIFT 描述子回退；两种描述子都执行双向一致性和 0.75 比率检查，训练帧与保留帧使用相同规则。原始录制不被改写。

ORB 时序几何筛选失败时，原始录制中间隔不超过 3 对的近邻帧再尝试金字塔 LK 光流，最后尝试 SIFT。光流往返误差须低于 0.8 个光流图像像素，并检查跟踪状态和光度误差。光流及 SIFT 坐标恢复到原始分辨率后接受同样的几何筛选。保留帧不参与时序特征跟踪、焦距或位姿估计。RANSAC 剔除误匹配，匹配须覆盖 8/12 网格，并排除主导单应性的退化观测；没有降低最终质量门槛。

`JointFocalEstimator` 先记录两眼各自的候选焦距及残差，单眼曲线平坦时不立即退出。随后联合左右时序约束与双目基础矩阵，在完整范围（最长边的 0.3～3 倍）进行网格搜索和多初值局部优化，避免弱单眼估计的 ±20% 范围锁住错误解。

联合优化后，分别把每眼焦距扰动 ±20%，每次都重新优化另一眼，检查联合目标是否明显变差。这个检查防止把“焦距比例确定、绝对尺度未知”误认为可靠标定；仍不可观测、边界解或残差过大时拒绝导出。随后恢复左右相对位姿，用实测基线确定尺度；正深度检查的远点阈值按基线单位设置为 1000，避免默认 50 把小基线相机的室内远点过早剔除。

这是受约束的自标定：假设主点位于图像中心、方形像素、固定焦距、畸变可忽略。不会估计径向或切向畸变。明显畸变、鱼眼或主点偏移较大的相机应提供实测 `K/D/R/T`。不要把本方法当作任意镜头的完整标定。

保留图像对不参与焦距、位姿估计。独立验证要求至少 3 对且至少 60% 通过；匹配覆盖 8/12 网格，纵向误差第 80 百分位不超过界面的验证阈值（默认 1.5 px），至少 85% 为正视差。失败时不导出标定、不启动米制地图。成功后保存 `rectified=false` 标定及模型假设和验证结果，由现有 `StereoRig` 去畸变/校正并进入 SLAM。

请对准有远近层次的静态场景，左右及上下平移，同时绕不同方向轻微转动。静止、纯平移、纯转动、单面墙、动态人物或模糊画面可能使标定退化。通过极线检查也不保证测距尺度精度，实机应另用已知距离验证。

## 日志与重试

诊断由 Java 同时输出到 IDE 控制台和 `self-calibration.log`，每次运行用 `BEGIN run=<UUID>` 分隔：

- `BEGIN / SEQUENCE / GATES`：运行版本、尺寸、基线、参数、录制数、选中的文件与阈值。
- `FRAME / STEREO_SUMMARY`：原始及增强后 ORB 特征数、提取方法、双目匹配方法与数量、SIFT 特征数、平均亮度、拉普拉斯方差（清晰度参考，不单独判定失败），以及满足匹配数量/覆盖要求的保留帧数。保留帧不足不能用已有标定过滤匹配后“补齐”。
- `PAIR`：具体两帧、眼别、ORB、LK 或 SIFT 方法、匹配数、RANSAC 内点数、网格覆盖、单应性比例、像素位移中位数、耗时和接受/拒绝原因。
- `TEMPORAL_SUMMARY`：左右接受的时序约束数及各筛选原因计数；总是在焦距估计之前输出，因此早期失败也有证据。
- `CONSTRAINT / STEREO_CONSTRAINT`：接受的时序及双目基础矩阵数值，便于复现焦距求解问题。
- `FOCAL_SEED / FOCAL_PROFILE / FOCAL_JOINT`：两眼单独候选、重新优化另一眼后的扰动残差，以及最终联合结果。单眼候选不等于已确认的镜头参数。
- `POSE / RIG / HELDOUT / VALIDATION_SUMMARY`：正深度点数、外参、每对独立验证误差及汇总。
- `SUCCESS / FAILED`：结果、总耗时或完整异常堆栈。

`too_few_matches` 表示匹配数不足，`raw_coverage` / `inlier_coverage` 表示覆盖筛选失败，`ransac_inliers` 表示内点数或比例不足。`homography_dominant` 表示匹配主要能由单应变换解释，可来自平面、纯转动或视差过小，不能仅凭这一项断定实际场景是平面。约束少于 6 组只说明筛选后数量不足，旧提示“有效运动帧不足”并不能证明用户没有移动相机。分析失败时请保留从 `BEGIN` 到 `FAILED` 的完整段落。

已有序列可以重试，无须重新录制：

```powershell
.\docs\slam\run-auto-slam.ps1 -BaselineMetres 0.065 -SequenceDirectory D:\path\to\auto-sequence -EyeWidth 640 -EyeHeight 480 -CalibrationOnly
```

`BaselineMetres` 必须换成实测值。输出使用 UUID 命名，不覆盖旧标定。旧的 `self-calibrate.py` 等脚本仅作为历史实现保留，Java 和 PowerShell 自动标定入口均不调用它们。

## 验证

```powershell
mvn -Pslam-tests test '-Dslam.opencv.library=C:\path\to\opencv_java490.dll'
```

50 项 Java 测试通过，包括弱单眼与强单眼联合恢复、共同尺度不可观测拒绝、弱对比度匹配、SIFT 对旋转和曝光变化的回退、多方向运动下的已知焦距恢复、短片段采样与保留帧隔离、光流亚像素运动恢复、空白图像拒绝和失败筛选日志，以及已有 SLAM/校正测试。合成验证不能代替相机实拍精度评测。

完整合成验证使用已有 30 对纹理场景，左右各接受 113 组时序约束，两眼联合焦距估计为 491.40 / 491.46 px（真值 500 px），6 对保留帧全部通过，纵向误差第 80 百分位为 0.92～0.99 px。该序列运行约 17 秒，耗时依赖硬件。

本次实机日志已明确显示：左右接受 28 / 26 组时序约束；旧版在左眼候选 325.56 px 的曲线变化量约 1.08e-6 时提前退出，没有评估右眼和联合约束。同时 60 对原始双目匹配平均仅 24.25 个，只有 10 对达到 60 个，12 对保留帧中只有 2 对达到匹配数门槛，因此仅修改焦距判断不足以保证验证通过。当前实现同时改进匹配与联合求解；未取得该实机的原始图像，不能把合成测试结果当作实机已修复的证据。
